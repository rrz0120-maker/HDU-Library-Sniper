## 安装：保留 P5.2

1. 使用原来成功预约的**同一个 Firefox 普通浏览模式、同一个校园账号**。不要清除官网数据、卸载插件、删除 IndexedDB 或切换到无痕模式。
2. 在 Firefox 打开 [P5.3 安装链接](https://raw.githubusercontent.com/rrz0120-maker/HDU-Library-Sniper/feat/android-p53-2000-single/userscripts/hdu-p53-2000-single.user.js)。Tampermonkey 应显示独立名称“杭电图书馆 P5.3 四楼162单次整点预约”、版本 **5.3.0**、仅匹配 `https://hdu.huitu.zhishulib.com/*`。点击安装。若只显示源码，用 Tampermonkey 管理面板 → 实用工具 → 从 URL 安装，粘贴同一链接。
3. **保留原 P5.2 脚本和数据**。可在扩展面板停用 P5.2 来减少界面遮挡，不要卸载它或清除数据。其原安装文件 SHA256 未改变。新文件采用独立名称和 namespace，不覆盖旧脚本。
4. 在[官网](https://hdu.huitu.zhishulib.com/#!/Space/Category/list)正常登录，刷新页面。右下方应出现默认收起的 **P5.3 · 162** 按钮；展开后只有“准备抢座 / 停止自动任务 / 查看结果”三个主要操作。

校验文件：[SHA256SUMS](../userscripts/SHA256SUMS)。正式交付消息中的 commit 固定链接可避免分支以后变化。脚本没有远程依赖和自动更新。

## 先做手机只读待命演练

**本轮开发环境无法操作你的真实手机。以下演练必须由你在手机上完成；Mock 通过不代表真机演练或真实 14 小时预约已通过。**

1. 展开 P5.3，保持“启用 11 月 17 日正式任务”**未勾选**，点“准备抢座”。
2. 应显示“只读演练通过 · 未启用提交”，并核对目标日期、08:00–22:00、50400 秒、162 → 62726、房间 1558。确认北京时间与手机自动校时一致，倒计时持续变化，面板不横向溢出。
3. 展开“运行日志（脱敏）”，检查 `LOGIN_OK`、`RANGE_OK`、开放日期、实际用于映射的 `mapDate` 及 `REHEARSAL_PASSED`。不显示 UID、密码、Cookie、姓名和接口全文。
4. 演练只读取登录、目录、一个已开放时段的座位图和已有预约；其中 `searchSeats` 虽使用 HTTP POST，语义是**只读座位查询**，不会调用预约 POST。旧日期座位即使占用，也只用于确认物理 ID，不推断 11 月 19 日是否空闲。
5. 点“停止自动任务”，确认已停止且没有预约。只读演练不创建正式任务、不消耗正式次数；再刷新、展开、做一次只读检查，确认 P5.2 记录仍可读取。避免反复快速点击查询。
6. 保存或长按复制脱敏日志。**先停在这里，确认真机只读演练通过后，再决定是否启用正式任务。**

`P52_RECEIPT_REQUIRED` 表示没有找到**同账号、本浏览器**的 P5.2 `SUCCESS + recordVerified + attempts=1` 记录。先在 P5.2 点“查看预约结果”核实它；不要伪造、重置记录，也不要重新预约来凑记录。若历史映射不匹配、存储不可用、登录失效、日期或时长规则未知，停止并保留日志。

## 19:59–20:00 实战

前提：手机只读演练通过；你确认馆方允许这一使用方式及“20:00 开放后天”的规则；确实需要本次座位和 14 小时时段。

1. **11 月 17 日 19:59 前后**，在同一 Firefox 打开已登录官网。使用普通模式，手机开启自动日期时间，保持网络、前台及屏幕唤醒。可提前延长一加系统“自动息屏”时间。不要同时用其他设备或官方表单操作此账号。
2. 核对完整目标，主动勾选确认框，然后点一次 **准备抢座**。正式准备允许在 **19:58 至 20:00 前**开始，并必须在 20:00 前完成。勾选本身不预约；此次点击只读准备后才进入“已授权待命”。
3. 登录、开放范围、14 小时规则、162 的唯一映射、同账号旧版本已消费凭据、目标时段冲突及存储全部检查通过后进入倒计时。11 月 19 日尚未列在可选日期里不会单独导致放弃；允许它是当前排他上界，但不接受明显不匹配的日期范围。
4. 保持页面前台，不刷新、不换账号、不锁屏。20:00 前不会正式提交。手机时间和馆方 Date 响应的保守时间下界都达到开放时点后，原子写入意图、新鲜签名、直接同源调用 `bookSeats` **一次**。整点不重新读取整个座位图或逐级点击网页。
5. 界面立即显示首次请求的状态和响应分类。成功响应后仍须读取官方记录；日期、08:00 开始、22:00 结束、50400 秒、四楼 162、有效状态全部一致，才显示 **SUCCESS — 162号预约成功**。

正式任务一旦已落库，刷新、双击、另一标签页和重开浏览器都不能重建它；不会自动恢复提交。停止待命也不会“释放次数”。如果准备失败、暂停或过时，请手动接管，不能通过清除数据重新抢。

## 失败后切换微信

| 状态 | 含义与操作 |
|---|---|
| **SUCCESS** | 官方记录完整匹配，任务结束。可在官方“我的预约”再核对。 |
| **FAILED** | 馆方明确拒绝；座位/日期拒绝还须经一次官方记录查询未发现目标成功记录。限流或认证失效直接停止自动请求。没有重试队列或备用座位。 |
| **UNKNOWN** | 包括请求尚在等待响应、404、超时、网络错误、成功响应但记录尚未更新、请求发出后停止。**不等于预约失败或取消。** |
| **已停止** | 未能继续准备/待命或尚未发出即停止；如存在写入意图，以持久记录和官方核验为准。 |

决定手动接管时，点 **停止自动任务**，再切到微信公众号，按你自己的选择使用另一个账号手动操作。程序不控制微信、不更换账号、不取消任何预约。切到后台也会触发停止保护。已经发出的请求仍可能成功，应保留 UNKNOWN 并稍后核查 Firefox 账号的官方记录。

响应后最多自动查询官方记录 **1 次**，没有自动轮询；后续主动“查看结果”最多再查 **2 次**，总预算 3 次跨标签页和重启保留，相邻核验至少 2 秒。到达预算或仍无法确认时使用官方“我的预约”。读超时 5 秒、写超时 30 秒沿用现有客户端；不必等满 30 秒才能点击停止或手动接管。停止会中止浏览器等待，但无法撤销服务器处理。

## 计时、记录与边界

- HTTP Date 仅秒级，脚本以 `performance.now()` 与墙上时钟的共同经过时间计算保守下界，并留 250ms 保护量；不会使用乐观的 RTT 中点校时提前发出。校时请求 RTT 超过 2 秒、手机与响应偏差超过 5 秒、样本超过 120 秒、时间变化或页面暂停均停止。正常情况下也会保守晚于整点；不能宣称毫秒精度。
- 为防 Android 唤醒后追赶旧任务，手机时间或馆方时间区间上界超过 **20:00:10** 即停止，可能更早止损。冻结/后台不会自动续跑。浏览器前台不保证操作系统一定按时调度。
- 日志分别记录登录、目录、ID 解析、冲突核验、本地提交前处理、`fetch` 调用时间 `dispatchAt`、收到响应头时间 `responseAt`、响应体解析和记录核验耗时。`dispatchToHeadersMs` 包括网络、排队和服务端时间；上传耗时与纯服务端处理时间不可单独测得，标为 `null`。这不是抓包级发送时间，也不是 20:00 高峰实测。
- 新库 `hdu-p53-formal-booking` 使用“账号哈希 + 日期 + 时段”键，严格持久化事务先记 `attempts=1 / UNKNOWN` 再调用请求。localStorage 保存额外的停止和已消费标记。没有删除/重置接口。异常关闭若来不及保存响应，只能保留意图及 UNKNOWN，不能编造响应或实际发包时间。
- P5.2 的 `hdu-p51-single-write` 只读。它同账号的一次额度已永久消费，旧脚本即使同时启用也不能再次提交。本保护依赖**原浏览器中的真实成功记录**，不能推广成跨设备、无痕窗口或手动官方操作的全局幂等。
- 官网会话自动用于同源请求。UID 只从现有合法登录响应读取到内存供既有签名使用，不让用户输入/导出，不写日志；持久化只使用账号哈希。不读取 Cookie，不保存密码，不向第三方发送认证信息。
- 不要清除网站数据、重装或换浏览器绕过预算。IndexedDB 严格事务和重启测试不能保证遭遇系统损坏、存储被清理或硬件故障时仍保留全部数据。若记录丢失，交由人工核对，不重新启用同一任务。
