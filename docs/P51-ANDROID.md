# 一加安卓手机单次预约测试（P5.2）

P5.2 已修复真实Unix秒级日期并核实不包含上界；已有用户先看[更新步骤](P52-DATE-COMPAT.md)。

交付物是 [hdu-p51.user.js](../userscripts/hdu-p51.user.js)。仅需 Firefox for Android + Tampermonkey，不需要 Linux、云服务器或 Docker。脚本在官网内使用同源会话；不读取/导出 Cookie，不要求填写 UID、密码，不向第三方发送认证数据。不能保证预约成功。

**当前仅交付普通时段、1 小时、单座位测试。手机安装和登录已由用户只读验证；真实座位信息和预约尚未验证。20:00 模式尚未开发。**

## 手机上安装

1. 安装或更新 **Firefox for Android**，使用普通浏览模式。Mozilla 插件目录当前标注 Tampermonkey 5.5.0 支持 Android Firefox **120+**；建议使用最新版。
2. 在 Firefox 菜单的“扩展”中安装并启用 [Tampermonkey 官方插件](https://addons.mozilla.org/android/addon/tampermonkey/)。也可以用 Firefox 打开此链接安装。
3. **在 Firefox 中**打开[脚本安装链接](https://raw.githubusercontent.com/rrz0120-maker/HDU-Library-Sniper/feat/android-p51-userscript/userscripts/hdu-p51.user.js)。检查名称“杭电图书馆 P5.1 单次预约测试”和匹配网址 `https://hdu.huitu.zhishulib.com/*`，在 Tampermonkey 页面点击“安装”。
4. 如果 Firefox 只展示源码，打开 Tampermonkey → 管理面板 → 实用工具，使用“从 URL 安装/导入”，粘贴上面的脚本链接。无需开发者工具或 CSS 选择器。不要安装来历不明的同名脚本。
5. 在**同一个 Firefox** 打开[官网座位预约页面](https://hdu.huitu.zhishulib.com/#!/Space/Category/list)，由你自行完成正常登录。其他浏览器的登录不会自动同步到 Firefox。不要把账号、密码或 Cookie 发给开发者。
6. 刷新页面，点右下方 **“P5.2 预约测试”** 展开面板。若没出现，检查 Tampermonkey 和脚本已启用、该网站的扩展访问权限已允许，且地址栏仍为上面的官网域名。不要在登录跳转域名上强行运行脚本。

脚本无外部依赖、无自动更新；后续版本需明确安装。Firefox 扩展安装/注入是否在你的具体一加系统上正常，仍需按下面的只读步骤验收；桌面 Firefox 引擎测试不等于一加真机验证。

## 首次只读检查（先停在这里）

1. 点 **检查登录状态**：应显示“官网登录有效”，不显示 UID 或姓名。失败时回官网正常登录，不绕过验证码或访问控制。
2. 点 **查询开放日期**：读取自习室目录、日期字段实际类型和允许时段。界面只提供能可靠解析的开放日期。
3. 选未来日期、实际需要的整点开始时间，固定 **1 小时、1 人**，选择 **162 或 157**。
4. 点 **查询四楼162/157**：核对区域“宋韵云图（四楼）”、两座内部 ID、所选时段状态、冲突预约数。空闲只针对本次时段，不意味着其他日期空闲。
5. 点 **准备预约**：会重新只读核对登录、范围、映射、所选座位空闲及冲突。应完整展示日期、开始/结束时间、1 小时、楼层、座位。**两个确认框仍未勾选，提交按钮不可用。**
6. 点 **查看运行日志 / 复制脱敏日志**，保存首次检查结果。日志只包括固定错误分类、范围字段、座位映射及耗时，不含密码、Cookie、UID、姓名或完整接口原文。如果复制权限被拒，日志框会选中文本，可长按复制。

### 日期字段与上界

P5.2 已按用户真实日志支持 `advance_date / max_date` 的Unix秒级安全整数，要求精确对应上海零点，仍兼容 `YYYY-MM-DD`。官网日期控件证明 `max_date` 不包含当天，详见[证据和样本转换](P52-DATE-COMPAT.md)。毫秒量级、非零点、异常日期等仍会安全停止；不要把可选日期当成正式写入开放的证明。

其他未知接口结构、重复/缺失 ID、未知座位状态、无法核对时钟、无持久化能力，也会拒绝提交。不要通过手改脚本跳过检查。

## 明确授权后的一次真实验收

先确认馆方允许该使用方式，且你确实需要使用该座位。关闭其他预约脚本、其他标签页中的预约操作，勿同时在官方表单提交。

1. 如准备方案超过 **5 分钟**，重新“准备预约”（仍是只读）。改变日期、时间或座位会清除确认状态，必须重新准备。
2. 核对完整方案；只有你明确决定提交时，勾选“实际需要使用1小时”和“馆方允许、授权本次最多一次提交”两个确认框。
3. 点 **确认提交一次预约**。程序重新只读检查，先持久化意图，再发出最多一次预约 POST。不会预锁、并发提交、自动尝试另一个座位、签到或取消预约。
4. 保持 Firefox 前台、屏幕唤醒、网络正常。服务器响应后最多进行一次自动只读核验；限流/认证失效时直接停止。日期、时间、时长、座位和区域全部与官方有效记录匹配才报告“预约成功”。
5. 在官网预约记录中自行再核对。测试成功后正常使用座位，不要为测试连续占用、取消和重约。

**超时、404、响应不明**：可能已经受理。没有匹配记录时保持 `UNKNOWN`，不重发、不换座位。你可主动点“查看预约结果”做额外只读核验；仍不明则交由人工核对。明确占用、冲突、限流或认证失效都会停止。

**停止当前任务**：中止本地后续请求，不取消已有预约。已发送请求可能已经在服务器完成；落库后尚未发出就停止，也会保守消耗一次额度并保留 UNKNOWN。

## 防重复保护的边界

- 每个账号在**当前 Firefox、当前官网存储**中，P5.1 整个验收最多一次正式写入。被拒和结果不明也消耗额度。没有删除/重置按钮。
- 原子 IndexedDB 事务可防多标签页、双击、刷新、关闭再打开浏览器导致重复发送。持久化失败则禁止提交；后台暂停后恢复时若确认过期，也不发送。
- 不同设备、浏览器、无痕窗口及原 Rust 程序不共享本机记录；官网接口没有可用的跨设备幂等键。因此**不能承诺跨设备防重复**。不要清除网站数据、重装浏览器、换设备或删除数据库来重复测试。
- 运行日志保留当前页面最近40条，可主动复制；一次写入状态和验收结果保存在本机 IndexedDB。新页面不自动发请求，需主动查看结果。
- MD5 只用于复现现有官网 `Api-Token` 契约，账号标识在持久化记录中使用 SHA-256；Cookie 由浏览器自动附加到同源请求，脚本不读取它。
