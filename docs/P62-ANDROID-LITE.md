# Android P6.2 Lite 安装与使用

本版本用于 Android Firefox + Tampermonkey，处于真机待验收阶段。默认预约宋韵云图（四楼）162号、后天 08:00–22:00，计划于北京时间 20:00:01.350 交出正式 POST。

## 安装

1. 下载 `HDU_Android_P6.2_Lite.zip` 并解压，得到同名 `.user.js` 和本说明。ZIP 需要先解压再导入。
2. 在 Android Firefox 的 Tampermonkey 管理面板中，通过「实用工具 → 从文件导入」选择 `HDU_Android_P6.2_Lite.user.js`，确认安装。也可以打开 GitHub Raw 安装链接由 Tampermonkey 接管。
3. 停用之前的 HDU 手机预约脚本，关闭旧馆方标签页，再新开 `https://hdu.huitu.zhishulib.com/` 并正常登录。
4. 右下角显示「P6.2 · 162」。若提示检测到旧版，完成停用后重新打开页面。

## 预约

展开面板，核对预约日期、开始和结束时间。默认 08:00–22:00，可选 07:00–22:00 内馆方允许的整点范围。首发偏移可设置为 800–2000 毫秒。

建议提前一两分钟点「启动正式预约」。身份与时段检查完成后会显示「等待20:00」。请保持 Firefox 前台和屏幕常亮，开启系统自动校时。每次启动只有一次正式预约 POST。

准备失败或尚未发送时，修正问题后可重新启动。点击「停止待命」只取消当前尚未发出的任务。隐藏、冻结和 pagehide 会保留当前待命，恢复前台后检查实际时间。同日恢复若已过计划时刻，会立即按当时时间发送并显示真实延迟。跨日恢复显示本次未发送，需要核对新日期并重新启动。

刷新会结束原页面的零提交等待，新页面需主动重新启动。已经发出的未决申请在刷新后保留去重记录，可点击「核验官方记录」。

## 查看结果

- 「正在发送」表示浏览器已经接手 POST。
- 「服务器已受理」要求馆方返回 `CODE=ok` 且 `DATA.result=success`，随后只读核验。
- 「预约成功且记录已核验」要求有效预约记录的开始秒、时长、房间、座号及存在的座位 ID 均匹配。
- `NOT_OPEN`、`SEAT_UNAVAILABLE` 等明确拒绝会结束本次申请。`LIMITED` / HTTP 429 立即停止写入，保留至少 10 分钟及更长 `Retry-After` 的限制。
- 断网、超时、HTTP 404、HTTP 异常及无法解析的回执显示「结果待核实」。官方记录暂未出现或读取失败时保留未决标记，支持主动继续核验。

人工再次申请距本脚本上次写入至少 10 秒。此间隔来自限流实测，已有额度消耗时仍可能被馆方拒绝。等待结束后也须本人重新启动。

「复制诊断日志」导出字段白名单 JSON。HTTP、业务码、服务器受理、官方核验及实际发送次数分开记录。未知业务码导出为 `OTHER`，原始原因仅在当前页面显示。剪贴板不可用时可长按日志文本复制。

`dispatchAt` 在浏览器 `fetch` 调用处采样，位于必要的同步意图记录之后。`requestStartAt` 为可获取时的浏览器 Resource Timing 请求起点。系统暂停、主线程拥堵和设备时钟偏差都可能影响时机。HTTP Date 不参与调度。进程恰在意图落盘和 fetch 交出之间消失时，发出次数和时刻显示未知。
